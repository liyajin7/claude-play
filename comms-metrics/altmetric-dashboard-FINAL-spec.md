# AISI Altmetric Dashboard — Full Spec

## What this builds

Two components that work together:

1. **`scrape.js`** — a Node script that crawls `aisi.gov.uk/research`, follows
   each research page, extracts arXiv IDs, and writes `papers.json`. Run once
   to set up, then weekly (manually or via scheduler) to pick up new papers.

2. **`index.html`** — a local browser dashboard. Reads `papers.json` on load,
   fetches Altmetric scores for all arXiv papers, and displays cards with scores,
   mention breakdowns, and sparklines. No manual paper entry — papers come
   entirely from the scraper.

**Why two components**: fetching `aisi.gov.uk` HTML from a browser is blocked
by CORS (browsers cannot read cross-origin HTML unless the remote site opts in
— AISI's site does not). Node has no such restriction. The Altmetric API does
allow cross-origin requests, so that half runs in the browser fine.

---

## Tech stack

- **Node.js 18+** for `scrape.js` — uses built-in `fetch`, no npm install needed
- **Vanilla JS + HTML/CSS** for `index.html` — zero external dependencies
- **localStorage** for caching Altmetric API responses between sessions
- A **local file server** to serve `index.html` — required because the
  `file://` protocol blocks `fetch('./papers.json')`. Use:
  ```bash
  npx serve .         # recommended
  # or:
  python3 -m http.server 8080
  ```

## Part 1: `scrape.js`

### What it does

1. Fetches `https://www.aisi.gov.uk/research`
2. Parses all research entry links from the listing page
3. For each entry, fetches the individual research page (500ms delay between
   requests — be polite to aisi.gov.uk)
4. Finds the "Read the full report" link on each page and classifies it:
   - `arxiv.org/abs/{id}` → `type: "arxiv"`, extract the arXiv ID
   - anything else (internal AISI URL, external non-arXiv) → `type: "other"`
5. Reads the existing `papers.json` before overwriting (to compute new-paper diff)
6. Writes fresh `papers.json`
7. Appends one line to `.scrape-log`

### AISI page structure (verified — do not guess)

**Listing page** (`/research`): server-side rendered HTML. Each entry is an
`<a>` tag with href matching `https://www.aisi.gov.uk/research/{slug}`.
Filter out `/category/` links and the root `/research` link itself.

**Individual research page**: contains one "Read the full report" link.
Examples of what this link points to:
- `https://arxiv.org/abs/2602.21831` — arXiv paper (most entries)
- `https://www.aisi.gov.uk/frontier-ai-trends-report` — internal page (no arXiv)

No headless browser needed — plain `fetch()` returns full HTML.

### Parsing (regex — no HTML parser library needed)

```js
// Extract all research entry links from listing page
const entryLinks = [...html.matchAll(/href="(https:\/\/www\.aisi\.gov\.uk\/research\/[^"\/]+)"/g)]
  .map(m => m[1])
  .filter((v, i, a) => a.indexOf(v) === i); // deduplicate

// Extract "Read the full report" link from individual page
// Try both attribute orderings since HTML attribute order is not guaranteed
const reportMatch = html.match(/href="([^"]+)"[^>]*>\s*Read the full report/i)
                 || html.match(/Read the full report[^<]*<\/a>.*?href="([^"]+)"/i);

// Extract arXiv ID from a matched URL
const arxivMatch = url.match(/arxiv\.org\/abs\/([^\s"?#]+)/i);
// arxivMatch[1] gives e.g. "2602.21831"

// Extract category label (appears as a linked tag near the title)
const categoryMatch = html.match(/category\/[^"]+">([^<]+)<\/a>/i);

// Extract published date
const dateMatch = html.match(/<div[^>]*>\s*((?:Jan|Feb|Mar|Apr|May|Jun|Jul|Aug|Sep|Oct|Nov|Dec)\s+\d{1,2},?\s+\d{4})\s*<\/div>/i);
```

### Rate limiting

```js
const sleep = ms => new Promise(r => setTimeout(r, ms));

for (const url of entryLinks) {
  const result = await scrapePage(url);
  papers.push(result);
  if (i < entryLinks.length - 1) await sleep(500);
}
```

### CLI flags

```bash
node scrape.js                      # always scrapes, full output
node scrape.js --dry-run            # fetch listing only, print URLs, don't fetch pages
node scrape.js --check              # skip if papers.json < 7 days old
node scrape.js --check --days 3     # skip if papers.json < 3 days old
node scrape.js --silent             # suppress progress lines, still print errors + summary
node scrape.js --check --silent     # combination — safe for cron/launchd
```

### `--check` flag implementation

```js
if (args.includes('--check')) {
  const maxAgeDays = getArgValue(args, '--days', 7); // default 7
  try {
    const existing = JSON.parse(fs.readFileSync('papers.json', 'utf8'));
    const ageDays = (Date.now() - new Date(existing.scraped_at).getTime())
                    / (1000 * 60 * 60 * 24);
    if (ageDays < maxAgeDays) {
      if (!silent) console.log(
        `papers.json is ${ageDays.toFixed(1)} days old — skipping (threshold: ${maxAgeDays}d)\n` +
        `Run without --check to force a rescrape.`
      );
      process.exit(0);
    }
  } catch {
    // papers.json missing or unreadable — fall through and scrape
  }
}
```

`--silent` suppresses the `[N/M]` progress lines and the skip message, but
still prints errors and the final summary line. Still exits 1 on failure.

### `.scrape-log` format

After each successful scrape, append one line:

```
2026-03-17T12:00:00Z  42 papers found  (38 arXiv, 4 other)  2 new since last run
```

"New since last run" = arXiv IDs in the new `papers.json` not present in the
old one. Read old `papers.json` into memory before overwriting to compute this.
If no old `papers.json` existed, log `(first run)` instead of a diff count.

### Error handling in scraper

| Situation | Behaviour |
|---|---|
| Listing page fetch fails | Print error, exit 1 |
| Individual page fetch fails | Store `type: "error"`, log it, continue |
| "Read the full report" not found | Store `type: "no_link"`, log it, continue |
| `papers.json` already exists | Overwrite — always produce a fresh file |
| `papers.json` missing on `--check` | Fall through and scrape normally |

## Part 2: `index.html` dashboard

### Loading sequence on startup

1. `fetch('./papers.json')` — load paper list
2. Merge with cached Altmetric data from localStorage
3. Render all cards immediately using cached data (or loading/empty states)
4. Check for new papers vs `seen_ids` in localStorage — show "new" banner if any
5. For papers with stale or missing Altmetric cache (> 24h old): queue background
   fetches via rate-limited queue

If `papers.json` fails to load, show full-page message:

Show a dismissable amber banner above the card grid:

## Altmetric API

Base URL: `https://api.altmetric.com/v1/`

For arXiv papers: `GET https://api.altmetric.com/v1/arxiv/{arxiv_id}`

No API key. No auth headers. Rate limit: ~1 request/second.
Returns 404 if no Altmetric record exists for the paper.

### Response fields to use

```json
{
  "title": "Paper title",
  "altmetric_id": 12345678,
  "score": 47.3,
  "cited_by_posts_count": 120,
  "cited_by_tweeters_count": 85,
  "cited_by_newsoutlets_count": 4,
  "cited_by_policies_count": 2,
  "cited_by_wikipedia_count": 1,
  "cited_by_feeds_count": 8,
  "cited_by_rdts_count": 3,
  "history": {
    "1w": 5.2,
    "1m": 12.4,
    "3m": 30.1,
    "6m": 45.0,
    "1y": 47.3,
    "at": 47.3
  },
  "context": {
    "all": {
      "pct": 95
    }
  }
}
```

Caveats:
- `cited_by_policies_count` is sometimes absent on the free tier — default to 0
- `history` may be absent — hide sparkline silently if so
- `context` may be absent — hide percentile silently if so
- `score` is the field to use (also present as `altmetric_score` in some responses)

## Rate-limiting queue (browser)

All Altmetric API fetches must go through this queue — never call the API in
parallel.

```js
const queue = [];
let processing = false;
const sleep = ms => new Promise(r => setTimeout(r, ms));

function queueFetch(url) {
  return new Promise((resolve, reject) => {
    queue.push({ url, resolve, reject });
    if (!processing) processQueue();
  });
}

async function processQueue() {
  processing = true;
  while (queue.length > 0) {
    const { url, resolve, reject } = queue.shift();
    try {
      const res = await fetch(url);
      resolve(res);
    } catch (e) {
      reject(e);
    }
    if (queue.length > 0) await sleep(1100);
  }
  processing = false;
}
```

"Refresh all" button: calls `queueFetch` for every arXiv paper sequentially.
Shows progress in header: `Updating 3 of 38...`

## localStorage schema

One key only:

```js
// Key: "altmetric_cache"
// Value: object keyed by arxiv_id

{
  "2602.21831": {
    "last_fetched": "2026-03-17T12:00:00.000Z",
    "status": "ok" | "no_record" | "error" | "rate_limited",
    "data": { /* raw Altmetric API response */ }  // null if status !== "ok"
  }
}

// Key: "seen_ids"
// Value: array of arxiv_id strings seen on previous visits
["2602.21831", "2501.12345", ...]
```

Cache staleness: > 24 hours → re-fetch in background on next dashboard load.
Show stale cached data immediately; replace with fresh data when it arrives.

All localStorage reads/writes wrapped in try/catch (storage can be disabled
in some browser contexts).

## Sparkline implementation

The `history` object gives 6 values (1w → at). Normalise to SVG height and
draw a polyline — no library needed:

```js
function sparkline(history) {
  const keys = ['1w', '1m', '3m', '6m', '1y', 'at'];
  const points = keys.map(k => history[k] ?? 0);
  const max = Math.max(...points, 1);
  const min = Math.min(...points);
  const w = 80, h = 28, pad = 2;
  const coords = points.map((v, i) => {
    const x = pad + (i / (points.length - 1)) * (w - pad * 2);
    const y = pad + (1 - (v - min) / (max - min || 1)) * (h - pad * 2);
    return `${x.toFixed(1)},${y.toFixed(1)}`;
  }).join(' ');
  return `<svg viewBox="0 0 ${w} ${h}" width="${w}" height="${h}" aria-hidden="true">
    <polyline points="${coords}" fill="none" stroke="currentColor"
              stroke-width="1.5" stroke-linejoin="round" stroke-linecap="round"/>
  </svg>`;
}
```

If `history` is absent from the API response, return an empty string — don't
render the sparkline area at all.

## Automated weekly scrape setup

AISI publishes ~2–4 papers per month. Weekly is the right cadence — at most
7 days before a new paper appears in the dashboard.

### macOS — launchd (recommended over cron on Mac)

launchd is more reliable than cron on macOS because it runs the job the next
time the machine is awake if it was asleep at the scheduled time.

Create `~/Library/LaunchAgents/com.aisi.altmetric-scraper.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key>
  <string>com.aisi.altmetric-scraper</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/local/bin/node</string>
    <string>/ABSOLUTE/PATH/TO/altmetric-dashboard/scrape.js</string>
    <string>--check</string>
    <string>--silent</string>
  </array>
  <key>StartCalendarInterval</key>
  <dict>
    <key>Weekday</key><integer>1</integer>
    <key>Hour</key><integer>9</integer>
    <key>Minute</key><integer>0</integer>
  </dict>
  <key>StandardOutPath</key>
  <string>/ABSOLUTE/PATH/TO/altmetric-dashboard/.scrape-log</string>
  <key>StandardErrorPath</key>
  <string>/ABSOLUTE/PATH/TO/altmetric-dashboard/.scrape-log</string>
</dict>
</plist>
```

The README must tell the user to:
1. Run `which node` and replace `/usr/local/bin/node` with the actual path
2. Run `pwd` in the project folder and replace the `/ABSOLUTE/PATH/TO/` placeholders
3. Then load it: `launchctl load ~/Library/LaunchAgents/com.aisi.altmetric-scraper.plist`
4. To stop: `launchctl unload ~/Library/LaunchAgents/com.aisi.altmetric-scraper.plist`

### macOS / Linux — cron (alternative)

```bash
crontab -e
```

Add (runs every Monday 9am — use full path from `which node`):

```cron
0 9 * * 1 cd /ABSOLUTE/PATH/TO/altmetric-dashboard && /usr/local/bin/node scrape.js --check --silent
```

cron may not fire if the machine is asleep at 9am Monday — launchd handles
this more gracefully.
